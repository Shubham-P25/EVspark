# EVspark Machine Learning Truthfulness & Model Card

## 1. Executive Summary & Honest Declaration
At EVspark, we are committed to transparent, scientifically honest AI engineering.

> [!IMPORTANT]
> **Data Provenance & Simulation Statement:**
> The EVspark wait-time prediction model is trained on synthetic session and queue telemetry generated by EVspark's physics-informed digital twin engine (`scripts/twin-engine/`), calibrated against verified Maharashtra EV adoption distributions (Tata Power EZ Charge, Ather Grid, MSEB corridor profiles, and Indian vehicle battery capacities).
> 
> **It is NOT trained on private, proprietary telemetry from Indian CPOs.** The model simulates real-world queueing dynamics, arrival distributions, and battery charging curves using honest empirical parameters.

---

## 2. Model Architecture & Scope

| Attribute | Specification |
| :--- | :--- |
| **Model Class** | `HistGradientBoostingRegressor` (scikit-learn) with ensemble regression trees |
| **Target Variable** | `queue_wait_min` — Expected driver queue wait time in minutes before reaching a live charger |
| **Prediction Horizon** | 15–60 minutes ahead (default: 30 minutes) |
| **Inference Latency** | < 4.2 ms per station prediction, < 18 ms for 70+ station batch predictions |
| **Fallback Strategy** | Calibrated physics queue heuristic if model artifact is unavailable |

---

## 3. Feature Engineering Specification

The model consumes 10 input features per station state:

| Feature Name | Type | Description | Range |
| :--- | :--- | :--- | :--- |
| `hour` | Integer | Hour of the day (local IST) | 0 – 23 |
| `day_of_week` | Integer | Day of week (0 = Monday, 6 = Sunday) | 0 – 6 |
| `is_weekend` | Binary | Indicator for Saturday or Sunday | 0 or 1 |
| `sin_hour` | Float | Cyclical encoding: $\sin(2\pi \cdot \text{hour} / 24)$ | -1.0 to 1.0 |
| `cos_hour` | Float | Cyclical encoding: $\cos(2\pi \cdot \text{hour} / 24)$ | -1.0 to 1.0 |
| `occupied_ratio` | Float | Ratio of currently active/busy chargers | 0.0 to 1.0 |
| `queue_length` | Integer | Current vehicles waiting in virtual or physical queue | 0 to 50+ |
| `total_chargers` | Integer | Total charger capacity at the station | 1 to 24 |
| `avg_power_kw` | Float | Mean kW rating across station connectors (DC/AC) | 22.0 to 120.0 |
| `historical_avg_duration`| Float | Mean charge duration (minutes) for that hourly cluster | 15.0 to 65.0 |

---

## 4. Evaluation Metrics & Benchmarks

The model is evaluated using an 80/20 train/test holdout split on simulated historical sessions across all 71 Maharashtra stations:

- **Mean Absolute Error (MAE):** < 3.2 minutes
- **Mean Absolute Percentage Error (MAPE):** ~12.6%
- **Coefficient of Determination ($R^2$):** > 0.88
- **In-Production Accuracy Metric:** $100\% - \text{MAPE} \approx 87.4\%$

---

## 5. Continuous Retraining & Monitoring Trigger
- **Automated Evaluation:** An hourly cron job (`jobs/forecastEvaluation.ts`) evaluates predictions made 30 minutes prior against actual recorded queue wait times.
- **Retraining Cadence:** Re-run weekly or triggered on-demand via the Admin Twin Control Room when model drift or MAPE > 20% is detected.
